## Intent
Make one focused marketplace listing cost one YAML entry, not a day of hand work. Every channel (RapidAPI, Postman, /developers pages, API.market paste copy) is generated from one source, so a release updates everything at once and nothing drifts.

## Why
You said hand-splitting is a lot of work, and you're right. A generator is the condition that makes the split worth doing. Hand-made copies also drift from the real API, which is how false claims ended up on /developers.

## Outcomes
- `listings.yaml`, with one entry per listing: id, title, category (Rapid `x-category`), tags, endpoint list, marketplaces, wave, short and long description, free-tier quota.
- `gen-listings` writes these per listing: a trimmed OpenAPI spec containing only that listing's operations, a Postman collection, `copy.md` (paste-ready title, description, tags and pricing note for consoles without an API), and example responses captured from live calls.
- Wave 1 = the 20 rows marked wave 1 in the CSV: PDF Redact, QR Code Generator, PDF Merge, PDF Compress, Loan Amortization Calculator, JWT Decoder, Hash Generator, UUID Generator, BMI Calculator, PDF Watermark, PDF Split, Markdown→PowerPoint, JSON→PowerPoint, Image Resize, Image Converter, Video to GIF, Audio Converter, EPUB Generator, ISBN Validator, Invoice/Receipt Generator.

## Acceptance criteria
- `gen-listings` produces 20 wave-1 folders.
- Every spec validates (swagger-cli or equivalent).
- Every operation exists in the live `/openapi.json`. The generator fails if one doesn't.
- Every JSON endpoint has a real example response.
- No secrets in output. Example capture reads `FDP_API_KEY` by name from env.
