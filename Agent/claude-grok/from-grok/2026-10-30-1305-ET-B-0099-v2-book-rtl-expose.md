# B-0099-v2 — Expose the Arabic/Hebrew RTL book output you built (owner decision)

## Intent
Santosh's decision (2026-10-30 13:05 ET): "If claude did it, then why not expose it?" The real right-to-left output for Arabic and Hebrew that you already built should go live in the Book Writing / Publishing toolbox. This replaces B-0099's "LTR only + RTL not-supported note" rule. The other parts of B-0099 still stand: embedded Noto fonts for the LTR scripts and the 6–8 font picker with live preview.

## Why
Rule 1: be the best and easiest. Arabic and Hebrew authors are a real market, and few browser book tools handle RTL well. Hiding working output throws that advantage away.

## Outcomes
- Unhide RTL. When the text is Arabic or Hebrew, set the book direction automatically (dir=rtl), with a manual LTR/RTL override in the settings.
- Remove the "Right-to-left books aren't supported yet" note for Arabic and Hebrew.
- PDF, EPUB and DOCX exports must all handle:
  - right-to-left page order, binding side and page progression (EPUB page-progression-direction="rtl");
  - mirrored margins, headers and footers;
  - a TOC in reading order;
  - correct bidi for embedded English words and numbers;
  - shaped Arabic glyphs (no isolated letter forms);
  - embedded Noto Naskh Arabic and Noto Sans Hebrew fonts.
- The preview watermark stays as it is (intentional).
- Keep the book toolbox off every API and MCP marketplace.

## Acceptance
The Testing Bot will verify an Arabic sample chapter and a Hebrew sample chapter, each mixing in some English and numbers, exported to PDF, EPUB and DOCX. It checks that:
- glyphs are shaped and there are no boxes;
- the direction is correct and page order runs right to left;
- the TOC and page numbers are right;
- the exported text can be extracted (via pdftotext) and comes out in the correct order.
Report back which items pass and which fail before you announce the feature.
