# B-API-14 to 19 — API audit cycle 03 follow-ups

**How we work:** inspect the real code, interpret, push back on weak ideas, and pick the best implementation. Note: **B-API-01 to 12 are still open**; B-API-13 (MCP batch billing, P0) is in its own brief and comes first.

## B-API-14 (P1): Shared anonymous rate limiter
- **Intent:** the documented "10 calls/hour without a key" should be true.
- **Why:** one IP made ~74 keyless calls in ~3 minutes and only 6 got 429. `x-ratelimit-remaining` bounced 9 → 4 → 0 → 9, pointing to an in-memory counter per Railway replica. Impact is bounded (only 3 keyless routes: word-count, slug, case-convert), and the keyed counter is already shared.
- **Outcome:** one counter shared across all servers (Redis or DB), plus reset/policy headers (e.g. `x-ratelimit-reset`, `ratelimit-policy`).
- **Done when:** calls 11–15 within the hour from one IP all return 429, whichever replica serves them.

## B-API-15 (P1): One-path checkout + API terms
- **Intent:** get from Quick Buy to Stripe in the fewest clicks.
- **Why:** "Quick Buy $24" (home) and "Upgrade" (/pricing) go to Google sign-in with `returnTo=/` or `/pricing`; the chosen plan is lost and the user must find it again. API plans on /pricing have no cancel, cap/429 or invoice terms (workflow products do).
- **Outcome:** the chosen plan is carried through sign-in and lands directly on Stripe Checkout for that plan at the right price. /pricing API plans state: cancel any time, what happens at the cap (429), and invoices.
- **Done when:** signed-out Quick Buy → Google → Stripe Checkout for the same plan, no extra clicks.
- **Note (owner action, not code):** the Google consent screen shows a personal Gmail as support email; Santosh changes that in Google Cloud console.

## B-API-16: "Web passes vs API & MCP" table + one trial wording
- **Intent:** buyers know exactly what each purchase includes.
- **Why:** no page says whether web passes ($1/day, $4.99/mo) include API calls, or whether API plans unlock web/premium apps. The trial shows as "$0" (/developers), "Included" (/pricing) and "Free tier" (llms.txt).
- **Outcome:** one comparison table on /pricing (and linked from /developers) and one trial word used everywhere, including llms.txt.
- **Constraint:** the bundling facts themselves await Santosh's definition; build the table structure and wording now, fill in confirmed facts only.

## B-API-17: Fill workflow gaps
- **Intent:** cover the core document workflows developers expect.
- **Why:** PDF.co, ConvertAPI and iLoveAPI all offer these; we don't.
- **Outcome:** image → PDF and PDF → image, HTML/Office (DOCX/XLSX) → PDF, OCR, PDF protect/unlock, and background (async) jobs with webhooks for heavy/media work.
- **Done when:** parity with PDF.co's core set, each metered per execution and documented in openapi.json.
