## Findings

**P1 #1 — One trial use covers every download in a page load (same as #95 P1 #3).**
Core: 10 different numbered files in one load → one usage POST, 0→1/10. nonlatin: 7 files → 1. err: the 300-page and 73.6 MB files → 1. In N09 and L07 the shared count had become 10/10 during the load, and Download still delivered the file without the cap dialog. A fresh load at 10/10 shows "Today's trial uses are done … Monthly for $4.99 … Day Pass for $1". Owner ruling: charging per page load is P1.

**P2 #2 — Non-Latin labels become pictures, so the page numbers can't be searched.**
`drawTextAnywhere` renders any label that isn't WinAnsi (Cyrillic `Страница 1`, CJK `第 1`, Arabic `صفحة 1`, emoji, even `Seite № 1`) as one PNG, digits included. The rendering is good, but the number isn't text: no search, no copy, screen readers skip it, and each label adds an image (three.pdf 1.5 KB → 23 KB for Cyrillic). Hindi `पृष्ठ 1` is real text in FreeSans and looks right, but extracts as `पृϖठ 1`. Suggested: always draw the digits as Helvetica text and only the prefix as an image (or embed a subset font per script, as is done for Devanagari), and fix the ToUnicode map for Devanagari conjuncts. Mention in the page text that non-Latin prefixes are drawn as images.

**P2 #3 — The trial badge can sit on top of a bottom-right number.**
N06 (crop-offset.pdf, Bottom Right): on page 4 (negative-origin MediaBox) the number "4" is under the "Created with FreeDailyPro.com" badge and can't be seen. The other pages in that run were clear. For a trial user choosing bottom-right (one of the two "most common conventions" per the FAQ), a hidden number reads as "the tool failed". Suggested: when the number is bottom-right, move the badge (bottom-left or top) or offset it above the number.

**P2 #4 — Locale pages: tool UI and the printed words are English.**
de/ja: controls, hints, strapline, title and meta are English. More important for output: "Page 1 of 10" always prints the English words `Page … of …` (hard-coded in `pn()`), so a German user must use Custom prefix and loses the total. Suggested: translate the UI and print `Seite 1 von 10`, `1 / 10` etc. on locale pages, or offer a pattern field.

**P2 #5 — The video shows an older, smaller tool.**
See check 12. It undersells the current tool (no "Page X of Y", roman numerals, ranges, skip, batch) and shows "5 free uses" and "Free". Re-record it with the current UI.

**P2 #6 — The blog post contradicts the tool.**
See check 9. Telling readers to rotate first and to split the cover out sends them to two extra tools for things this tool already does well.

**P3 #7 — Limitations: "Password-protected files fail to load."** They load after the unlock dialog (verified with enc.pdf).
**P3 #8 — SEO details:** VideoObject `uploadDate` 2026-08-22 and name differ from the YouTube video (2026-09-30, "How to Use Add Page Numbers – Free Step-by-Step Walkthrough"); no `duration`; OG image is the site default; locale `<title>`/meta are English.
**P3 #9 — Accessibility:** axe desktop `label-content-name-mismatch` (serious, `.right-2`) and `region`; iPhone SE +9 px horizontal scroll (sitewide).
**P3 #10 — Range wording:** `0-3` says it is "outside this PDF's 3 pages"; "Page numbers start at 1" would be clearer.
**P3 #11 — Enhancements toward competitors:** a pattern field (`{n}`, `{p}`, text after the number), colour/opacity/margin, facing-pages (outside corners on odd/even), and section restarts. These would make the "wow" moment for thesis and legal users and give the paid pass more to sell.
