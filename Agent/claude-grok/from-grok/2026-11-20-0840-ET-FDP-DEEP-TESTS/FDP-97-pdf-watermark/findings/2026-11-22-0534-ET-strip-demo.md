# FDP-97 strip demo: is the watermark a separate, removable object?

**Answer: yes, as a unit.** It is not an annotation (no /Annots entry for the user's watermark), not an optional-content layer (no OCG/OCProperties), and not marked `/Artifact` (no BDC/EMC). It is one extra content stream per page, appended (on top) or prepended (behind):

```
/Contents [ "q", "q", original…, "Q", WATERMARK, "Q", BADGE ]      (doc.pdf page 1: streams 0–1, 2–7, 8, 9, 10, 11)
WATERMARK (text):  q /GS-9742682568 gs BT 0.502 0.502 0.502 rg /Helvetica-Bold-7098480789 50 Tf … (CONFIDENTIAL) Tj ET Q
WATERMARK (image): q /GS-9742682568 gs 1 0 0 1 333.2 331.75 cm … /Image-… Do Q
BADGE:             q … badge box and <4372656174656420…> ("Created with FreeDailyPro.com") … Q
```
Plus, for the trial badge only, one `/Link` annotation per page (Contents "Created with FreeDailyPro.com").

**Demo:** `scripts/strip97.py` (26 lines, pikepdf) drops every stream that uses a `/GS-n` state with a `/Helvetica-Bold-n` font or `/Image-n` XObject, and the badge stream. It needs no original.

**Context:**
- Most online watermark tools produce removable marks; PDF24 says so openly and points to Rasterize; Acrobat tags its watermarks as artifacts so they can be removed in Acrobat.
- The page's FAQ ("part of the document like any other page content") reads as "hard to remove"; "When not to use" correctly says it is "a visible label, not protection".
- Suggested: honest wording + "Make it permanent" (Flatten/Rasterize handoff). Marking the stream `/Artifact` would help screen readers; it does not change strippability.
- The trial badge is removed the same way: owner question Q2 (badge is intentional per OWNER-DECISIONS; not reported as a bug).
