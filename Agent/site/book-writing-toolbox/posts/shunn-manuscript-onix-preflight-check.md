Retailers and distributors lean on metadata formats most writers never hear named. Upload portals reject files for margin and cover issues that a careful check would have caught for free.

Book Writing Toolbox includes three “behind the scenes” pieces aimed at those gates: Shunn Standard Manuscript Format export, ONIX metadata export, and a free unlimited Pre-flight Check. None of them write your plot. All three reduce avoidable rejection.

## Shunn Standard Manuscript Format—why agents still care

Many agents and publishers still want manuscripts in a predictable shape: 12pt Times New Roman, double-spaced, 1in margins, a real running head on every page, and an honest word count. That format is not about aesthetics. It is about reading speed, annotation, and comparing manuscripts without decoding each author’s DIY layout.

Getting it wrong is an easy, avoidable reason for a pass that has nothing to do with whether chapter three works. Book Writing Toolbox generates Shunn-format output automatically from the same chapters you already wrote—as both .docx and .pdf—with real running heads and an honest word count rather than a rounded marketing number.

You do not retype the book into a second Word template. You export. Then you still proof the export once, because any automated layout deserves a human skim. Check that chapter titles survived, that scene breaks did not collapse, and that the running head shows the expected surname/title pattern.

## ONIX, in plain language

ONIX is a metadata format retailers and distributors use to list books correctly—title, contributors, identifiers, and related fields systems already expect. Writers rarely “author ONIX by hand.” Distributors and platforms often generate or ingest it behind the scenes. IngramSpark-heavy workflows in particular live in a world where clean metadata prevents wrong titles, missing contributors, and catalog glitches.

In Book Writing Toolbox, ONIX export is filled from information you already entered elsewhere: title, author, ISBN, publisher, and related project fields. The point is not to turn you into a metadata engineer. The point is to avoid re-keying the same facts into five portals with five typos.

> **Tip:** Treat ONIX export as a packaging step after the book content is stable. If you change title or ISBN, export again.

## Pre-flight Check: free, unlimited, real render + real EPUB build

Pre-flight Check is free and unlimited. It is not a popup that says “looks fine.” It runs a real render and a real EPUB build, then checks against the platform you selected:

- Trim size
- Page count
- Margin
- ISBN
- Cover resolution
- EPUB file size and accessibility signals

Frame it as: catch the problem before you pay for a clean download. Credits apply to clean book PDF/manuscript downloads from the shared pool; Pre-flight does not require you to spend those credits to learn you picked the wrong trim.

When Pre-flight fails, fix the listed issues, re-run, and only then buy a credit package if you need an unwatermarked print PDF. For EPUB, remember EPUB itself is always free and unlimited; watermark removal uses the separate EPUB & Manuscript Pass when you need clean files.

Accessibility shows up inside Pre-flight for a reason: EPUB Accessibility 1.1 / WCAG AA is only an honest claim when every image has alt text. Add alt text while you still remember what the figure is for—not the night before upload. If Pre-flight flags cover resolution, fix the source image instead of stretching a small JPEG.

## How the three fit together

Shunn export is for human gatekeepers—agents and editors who read double-spaced pages. ONIX is for machine gatekeepers—retail and distribution systems that need consistent metadata. Pre-flight is for platform gatekeepers—upload validators that enforce geometry, ISBN presence, cover pixels, and EPUB constraints.

A book can “look right” on your laptop and still fail all three. These tools close that gap using the chapters and project fields you already maintain.

## A submission-week checklist

1. Freeze the chapter text you intend to submit.
2. Select the correct publishing platform (or ebook-only target).
3. Run free Pre-flight until checks pass for that platform.
4. Export Shunn .docx/.pdf if you are querying agents or traditional editors.
5. Export ONIX if your distributor or retailer workflow needs it.
6. Download clean production files only after Pre-flight is green.

None of this replaces a human editor. It replaces the special class of failure where the writing was ready and the file was not.

If you juggle print and query submissions in the same month, keep the Shunn export and the print PDF as separate dated files. Do not overwrite your agent manuscript with a typeset proof by accident.
