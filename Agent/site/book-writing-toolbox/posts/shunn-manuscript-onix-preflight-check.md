## Shunn format: the layout agents still expect

Many literary agents and publishers want a predictable manuscript: **12pt Times New Roman**, **double-spaced**, **1in margins**, a **real running head** on every page, and an **honest word count**. The point is not beauty. It is reading speed, annotation, and comparing manuscripts without decoding each author’s DIY Word theme.

Getting Shunn wrong is an easy, avoidable pass that has nothing to do with whether chapter three works. Book Writing Toolbox generates this automatically from the same chapters you already wrote—as **.docx and .pdf**—with real running heads and an honest word count, not a rounded marketing number.

You do not retype the book into a second template. You export, then skim once: chapter titles intact, scene breaks alive, running head showing the expected pattern. Manuscript format will not fix a muddy middle. It will stop a tired first reader from fighting your layout before they meet your voice.

## ONIX without the jargon headache

ONIX is the metadata format many retailers and distributors use to list books correctly—title, contributors, identifiers, and related fields machines already expect. Writers almost never “hand-author ONIX.” Distributors and platforms ingest or generate it behind the scenes. IngramSpark-heavy workflows especially punish messy metadata: wrong titles, missing contributors, catalog glitches.

In Book Writing Toolbox, ONIX export is filled from information you already entered: title, author, ISBN, publisher, and related project fields. The goal is not to turn you into a metadata engineer. The goal is to stop re-keying the same facts into five portals with five typos.

> **Tip:** Export ONIX after content is stable. If you change title or ISBN, export again.

### Submission-week checklist

1. Freeze the chapter text you intend to submit.
2. Select the correct publishing platform (or ebook-only target).
3. Run free Pre-flight until checks pass.
4. Export Shunn if you are querying agents or traditional editors.
5. Export ONIX if your distributor workflow needs it.
6. Download clean production files only after Pre-flight is green.

None of this replaces a human editor. It replaces the special failure where the writing was ready and the file was not.

If you juggle agent queries and print uploads the same month, keep Shunn and print PDF as separate dated files. Do not overwrite your agent manuscript with a typeset proof by accident. When collaborators need clean downloads under the pass, coordinate the 24-hour window so everyone grabs files while it is active.

## Why “it looks fine on my screen” fails agents

Agents skim. Double-spacing, running heads, and honest word counts are a shared language. A creative PDF that looks like a finished trade book can feel like you skipped the submission norms of that market. Shunn export is the handshake, not the art.

Use Shunn for queries. Use typeset PDF for proof and print. Keep both. Label folders so a sleepy midnight send does not attach the wrong file to QueryManager.

## Pre-flight as a money filter

Every failed Pre-flight item is a future rejection email you did not have to receive. Cover resolution failures are especially common when authors export social-media JPEGs as “covers.” Fix the source image at real print resolution, then re-check.

ISBN failures often mean the platform expects a free exclusive number you never claimed—or an owned ISBN you never entered. Read the guidance the picker shows for that platform. It is not generic help text; it changes with the selection.
