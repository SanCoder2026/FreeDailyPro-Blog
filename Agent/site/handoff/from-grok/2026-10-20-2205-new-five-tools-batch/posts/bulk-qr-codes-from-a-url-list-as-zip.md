## When bulk is the right tool

Use bulk when every payload differs (unique URLs, coupon codes, seat rows). Use [Custom QR Code](https://www.freedailypro.com/tool/custom-qr) when one hero design needs logo and gradient treatment. Use [QR Generator](https://www.freedailypro.com/tool/qr-generator) for a single quick test.

## Worked example: eighty exhibitor pages

- List: one HTTPS URL per line from the registration export
- Optional naming: tick **Lines are name,value** so files carry booth codes

## Why index.csv is non-negotiable

Numbered files alone drift when someone renames "QR_017.png" by hand. The CSV is the map from file to payload. Archive it with the print order email so disputes ("wrong booth link") resolve in minutes.

## Common mistakes

- Pasting Excel rows with trailing spaces that change the payload.
- Using short, similar colours on coloured badge stock without a white underlay.
- Deleting the CSV to "tidy" the folder.
- Generating from a draft domain that still returns 404.
- Skipping the five-code scan sample.

## Limits and good to know

- Output is a ZIP of many codes plus index—not a single multi-page PDF.
- File names are numbered unless you use name,value lines.
- Large lists can produce large ZIPs; split by hall if your machine struggles.
- Trial usage rules for file tools still apply on Professional Tools.
- Decorative bulk runs still need contrast and quiet zones like any QR.

## Event-day rollback plan

If one booth URL is wrong, regenerate only that line in a mini bulk (or Custom QR), replace the single file, and update the CSV row. Do not regenerate the entire eighty unless the brand colours changed.


## Spreadsheet prep that prevents bad ZIPs

Export CSV from the registration system, open in a plain editor, and remove smart quotes. Confirm every line starts with `https://` when the payload is a URL. Sort by booth number so ZIP order roughly matches floor plan walkthroughs.

Diego keeps a `source_urls_final.csv` locked as read-only after generate day so nobody "fixes" a cell after badges print.

## Naming with name,value

When booth codes matter, paste lines like `A12,https://fair.example/a12`. Files then carry A12 in the name and the CSV still maps everything. Staff can find a reprint without opening every PNG.

## Color policy for outdoor tents

Default black on white for bulk event codes. Save brand colors for the badge frame around the code, not the modules themselves, unless you have already field-tested those colors on the same stock.

## Reprint SOP

Log booth, file name, reason (smear, wrong URL, torn). Regenerate only the needed rows in a second bulk job. Merge the new CSV rows into the master index rather than creating a second competing truth.

## Staff briefing card

"Scan any badge; if it opens the wrong exhibitor, photograph the badge and message ops—do not peel and restick randomly." That instruction stops silent floor chaos.

## FAQ-style notes

**ZIP too big?** Split the list by hall or day.
**Can I get one PDF of all codes?** Not this tool's primary output—use the ZIP files in your label software.
**Do I need Custom QR first?** Only for one-off branded heroes; bulk is for volume.


## Coordination with badge printers

Send the ZIP, the CSV, and a PDF proof sheet of the first ten codes. Ask the printer to scan codes 1, 40, and 80 from the printed badge stock before the full run. That three-scan gate catches density problems that look fine on office paper.


## Post-event analytics

Because each booth has a unique URL, campaign analytics can show which exhibitors actually drew scans. Export that report for next year's sales deck. If several codes share one generic homepage, you lose that signal—unique payloads are the point of bulk.


## Indoor arena versus outdoor fairground

Arena lighting is controlled; fairground sun washes low-contrast codes. For outdoor bulk runs, increase physical size 25% over the indoor badge size you used last year and keep black modules on white. Test one badge at noon, not only under the tent.
