## Steps on EPUB Maker

1. Split the manuscript so each chapter is its own .docx, .md, or .txt (or paste text into chapters).
2. Open [EPUB Maker](https://www.freedailypro.com/tool/epub-maker).
3. Add chapters and set order; optional chapter titles when the tool allows overrides.
4. Enter book title and at least one author (separate multiple authors with a semicolon).
5. Set language (for example `en`, `en-US`, `fr`, `es`).
6. Optional: ISBN with valid check digit, copyright holder, description, cover image.
7. Review the check panel and accessibility note before build.
8. Use the reading preview once chapters exist.
9. Build and download the EPUB.
10. Open the file in at least one desktop reader and one mobile reader before store upload.

## Accessibility note in plain terms

The tool reports accessibility status based on what you included. Example: a text-only book with no images can pass notes about alt text not being required and may declare EPUB Accessibility metadata when conditions match. If you add images, plan alt text and re-check—do not ignore the note.

## Store acceptance reality

Amazon, Apple, and other stores each have their own validators and packaging rules. EPUB Maker gives you an EPUB 3 structure to start from; always run the store’s current checker and fix issues they report. Treat the download as a strong draft package, not a guarantee of one-click acceptance.

## Common mistakes

- One giant .docx with no chapter breaks.
- Wrong chapter order and no preview pass.
- Cover that is a logo on a white square instead of a real front cover.
- Closing the tab without downloading—the project is not stored by FreeDailyPro.
- Assuming store upload will succeed without their validator.

## Naming and versioning

`Title_v1_proof.epub`, then `Title_v2_store.epub` after validator fixes. Keep chapter sources in a parallel folder so you can rebuild without hunting email attachments.

## Chapter hygiene before import

Strip tracked changes and comments from Word chapters. Mysterious revision text in an EPUB is embarrassing on a Kindle. Prefer “Accept all and save a clean export” the day before build.

## Cover file discipline

Name covers with title and size (`Title_cover_1600x2560.jpg`). Do not reuse a Facebook banner with the wrong aspect ratio and hope stores crop kindly.

## Dual-format authors

If you also need print PDF, do not treat EPUB Maker as the print engine. Use Book Writing Toolbox or your print path for paper; keep EPUB for reflow reading. Trying to force print layout into reflow EPUB frustrates both formats.

## Validator loop

Build → open in reader → store checker → fix chapters → rebuild. Budget an afternoon for the first book; later books go faster once your chapter template is stable.


## Sample chapter first

Build a one-chapter EPUB before the full twelve. Confirm fonts, quotes, and heading levels look right. Fixing structure on a sample is cheaper than rebuilding the whole book three times.

## Metadata that stores care about

Title and author must match the store listing exactly. Language codes should match the text. Description text can be short for proof builds and expanded later for the store page.
