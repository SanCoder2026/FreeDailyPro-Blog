## Worked example: one-day workshop, Denver CO

- Source: project schedule or lines like `09:00-09:45 | Opening keynote | Maya Chen | Ballroom A`
- Subtitle: date and venue; footer: website/contact
- Paper: US Letter; presenters and rooms on; tracks optional
- Done definition: print one proof, zero typos, titles fit one or two lines

## Steps on Agenda Builder

1. Lock session titles so they stay short.
2. Open [Agenda Builder](https://www.freedailypro.com/tool/agenda-builder).
3. Pull sessions from the project schedule or type one line per item (`time | title | presenter | room`).
4. For multi-day events, use day structure so each day gets its own heading and date format.
5. Set event title, colour, subtitle, footer.
6. Toggle Presenters, Rooms, Tracks as needed; preview updates.
7. Choose US Letter or A4 (follows project paper when set).
8. Download the programme PDF.
9. Print at **100% / Actual size**, not Fit to page.
10. Read one printed page for typos before the full run.

## Multi-day programmes

Each day gets its own heading. Long programmes continue across pages with page numbers. Keep titles short so wrapping stays readable on paper.

## Common mistakes

- Putting crew-only notes in the guest programme.
- Overlong titles that wrap into three messy lines.
- Printing Fit to page so margins shift.
- Skipping the single-page proof read.
- Expecting time-zone conversion—the tool shows times as entered.

## Colour and brand

Use one accent colour that matches badges and signage. Guests notice consistency more than elaborate design.

## Digital handout

Email the same PDF and print a stack at registration. Phone-friendly PDF beats a broken website when the venue Wi-Fi fails.

## Presenter name consistency

Match programme spellings to badge names. Guests notice when “Jon” and “Jonathan” appear for the same speaker. Pull names from one master list.

## Track colour vs programme colour

If you use tracks, keep the programme accent colour simple and put track names in text rather than a rainbow of illegible chips on paper.


## Registration desk stack

Print programmes at 100% on the same paper weight as other handouts when you can. Mix of flimsy programme and heavy badge stock feels accidental. Bundle programme + map insert with a single staple only if the page count stays small.

## Last-minute session swaps

When a speaker drops out an hour before doors, update the project schedule, re-export the programme, and print a small “version B” stack for the front row rather than hand-correcting fifty pages with a pen—unless the change is one word.

## Accessibility of the programme PDF

Use high-contrast text and avoid tiny footer type for essential contact info. Guests on phones pinch-zoom; guests over fifty appreciate larger session titles even more.

## Workshop vs conference tone

Workshops can list break times explicitly so people return on time. Large conferences sometimes hide micro-breaks inside blocks—decide intentionally so the programme sets expectations.

## Room capacity line

If a breakout seats forty, say so under the title when overflow is likely. Guests plan laptops and notebooks better when capacity is visible on the paper programme.

## Export naming

Save `Programme_WorkshopDenver_2026-10-24_v2.pdf` so registration does not print yesterday's file from the Downloads folder.

## Sponsor line placement

If a sponsor must appear, put them in the footer once rather than beside every session title. Guest eyes go to times and rooms first; cluttered sponsor logos on every line make the PDF hard to scan in a crowded lobby.

## Proof readers who are not you

Hand the programme to someone who did not build the schedule. They will catch doubled sessions and missing coffee breaks faster than the planner who has stared at the grid for a week.

## FAQ

**Uploaded?** No—browser PDF only.
