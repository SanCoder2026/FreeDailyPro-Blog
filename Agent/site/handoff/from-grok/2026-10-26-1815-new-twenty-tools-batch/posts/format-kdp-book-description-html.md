## What stores usually allow

Amazon KDP commonly accepts paragraphs, line breaks, bold, italic, underline, headings h4–h6, and bulleted or numbered lists. Stores change rules—always use the store preview. In plain-text mode: blank line starts a paragraph; lines starting with - become bullets; 1. starts a numbered list; # a heading; **bold**, *italic* and __underline__ work inline. Clean mode keeps allowed tags, turns divs into paragraphs, maps large headings down, and strips styles, classes, links, images and scripts while keeping text.

## Common mistakes

- Pasting Word HTML with tracked changes and inline styles straight into KDP.
- Writing past 4,000 characters and discovering truncation after publish.
- Using h1/h2 thinking bigger is better when stores prefer smaller heading tags.
- Putting live links or images into a description that strips them.
- Skipping the store preview and trusting only the tool preview.

## Edge cases

Translated descriptions: keep HTML structure identical across languages where possible. Series books: reuse a cleaned template and swap the hook line. Box sets: watch the character budget carefully for multi-book blurbs.

## Blurb structure that sells the click

Bold hook line, two short paragraphs of stakes, then a short bullet list of reader promises. End before you spoil the ending. Read it aloud once before you convert.

## Series and edition notes inside the limit

Series books burn characters fast if every blurb repeats the entire series pitch. Keep a shared 400-character series spine paragraph, then write a unique 600–900 character hook per title. Clean mode is useful when you paste from a web page that injects tracking spans—review the change list so you know what disappeared. Never rely solely on the in-tool preview; marketplace previews apply their own CSS and may collapse extra breaks.

## Mobile preview pass

Most store browsers show descriptions on phones first. After pasting HTML, open the store preview on a narrow window and ensure the bold hook is visible without scrolling past a wall of list items.

## Keywords versus description

The description is prose for humans; backend keywords are a separate field. Do not stuff the HTML with comma lists of search terms—that reads as spam and wastes the 4,000-character budget. Use the formatter for readable paragraphs and lists, then handle keywords in the store’s keyword boxes.

## Edition differences

Hardcover, paperback and ebook descriptions can share a spine paragraph but should note format-specific bonuses (large print, audiobook codes) only on the matching page. Clean HTML once, then fork the last paragraph per format.

Avoid pasting emoji-heavy blurbs if the store strips them inconsistently. Prefer words. If you clean existing HTML from a previous retailer, read the change list carefully—links and inline styles will disappear by design.

Keep a plain-text source of record for every live description. HTML in the store is a rendering, not your manuscript of marketing copy.
