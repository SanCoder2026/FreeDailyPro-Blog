## Common mistakes

- Different times on flyer vs .ics.
- Fit-to-page printing.
- Huge unoptimized photos slowing the tab.
- QR to a dead form.
- Updating one asset and not the others.

## Single source of time

Type the when field once and let the .ics use it. Hand-edited calendar files drift.

## Photo vs theme

A clean color theme often prints more reliably than a dark photo behind small type.

## QR destination policy

Point QR codes at a stable RSVP URL you control. Do not print QR to a temporary short link that may expire before the event.

## Proof circle

One non-planner proofreads date, doors time, and city. Most viral errors are human, not design.

## Version in the filename

Invite_Gala_2026-10-26_v2.pdf beats final_final_really.pdf in Downloads chaos.

## Production log

Write one line of settings and export date next to the final file for the create event invites flyers and qr job so a reprint does not start from zero.

## Channel matrix

Decide which asset goes to email, print, social, and lobby poster. Not every channel needs the banner crop; mismatched crops look careless.

## Color contrast

Check body text on photo backgrounds. If type fails contrast, switch to the solid theme rather than hoping mobile screens forgive it.

## Asset freeze date

Pick a freeze date after which only critical corrections ship. Social crops can still be made from the frozen master, but the master time and place do not drift per channel.

If a sponsor logo must appear, place it once in a footer zone rather than competing with the event title on every flyer.

## Archive and naming for create event invites flyers and qr

Store final exports under a folder named with the event or project code and the ISO date. Inside, keep `exports/`, `project/`, and `notes.txt`. In notes.txt for create event invites flyers and qr, record approver name, device used on the day, and version label. That beats a desktop full of final2 copies.


## Extra field practice

Build a one-row channel plan: email uses the invite crop, lobby uses the poster, social uses a square safe zone. Design once with safe margins so crops do not cut the date. Short links in QR codes should be owned by your org and set not to expire before the event ends. Print a single QR test poster and scan it from ten feet away in venue lighting before you commit a full run.


## Capacity and contingency

For create event invites flyers and qr, write a short contingency: if the primary laptop fails, which backup device opens the project; if the printer fails, which file is already on a USB stick; if the venue network fails, which steps still work offline. Contingencies written after the failure are just stories. Contingencies written before the event are operations.

Assign names, not roles only—roles change when people call in sick. List those people by name in the notes file that sits beside the create event invites flyers and qr export.
