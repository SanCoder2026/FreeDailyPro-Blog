## What the tool does

Count dietary needs and allergies and list access needs from your guest list, as a sheet for the caterer and venue. Choose confirmed and attended, or everyone except declined. ## Worked example

180-guest wedding: 22 vegetarian, 6 vegan, 4 nut allergy named, access list for two wheelchair users and one step-open seating request; caterer PDF 72 hours out, delta 24 hours out.

Done definition for export dietary and access summary: one project file, one export set, and no second spreadsheet that disagrees.

## Steps

1. Ensure dietary and access notes exist on each guest.
2. Open Dietary and Access Summary with the project.
3. Pick population: confirmed/attended or exclude declined.
4. Decide whether the food sheet includes names.
5. Generate the food sheet for the caterer.
6. Generate the access list for the venue.
7. Send 72 hours before; send a delta 24 hours before.
8. Save the project after late RSVP changes.
9. Do not invent codes the kitchen does not understand.
10. Keep a paper copy at the pass for service night.

## Common mistakes

- Notes like “maybe GF” without a decision.
- Sending counts without named severe allergies when labels need names.
- Skipping the 24-hour delta.
- Including declined guests in kitchen counts.
- Emailing the sheet from an outdated project.

## Limits and good to know

Only as good as guest-list notes. Not a medical system. Browser project unless saved.

## Named severe allergies

When meals are plated per person, include names. When buffet only, counts may suffice—but still flag life-threatening allergies in writing.

## Access is not food

Keep mobility and sensory needs on the access list for venue staff, not buried in the kitchen sheet.

## Code glossary

If you use V/VG/GF, attach a one-line legend the caterer already uses.

## Plus-ones

Ensure plus-one diet notes exist as their own guest rows when possible.

## Service night changes

Walk-up diet changes go to a single floor manager, then one annotated print—not five WhatsApp threads.

## Production log

Write one line of settings and export date next to the final file for the export dietary and access summary job so a reprint does not start from zero.

## Child meals

If children attend, give them explicit meal codes. “Same as parents” fails when parents eat vegan and children will not.

## Venue walk paths

Access lists should include which door is step-open. Venue staff need a door plan, not only a name list.

## Kitchen call window

Schedule a fifteen-minute call with the chef after the 72-hour send to confirm codes match their prep sheets. Misaligned codes are common when planners invent abbreviations kitchens do not use.

Access lists go to venue ops with a floor plan mark-up for step-free routes, not only a name column.

## Archive and naming for export dietary and access summary

Store final exports under a folder named with the event or project code and the ISO date. Inside, keep `exports/`, `project/`, and `notes.txt`. In notes.txt for export dietary and access summary, record approver name, device used on the day, and version label. That beats a desktop full of final2 copies.


## Extra field practice

Separate life-threatening allergies from preference counts when you brief the pass. Preferences can flex; anaphylaxis risk cannot. Ask caterers which label format they want—name on ticket versus kitchen board—before you toggle names on the food sheet. For access, include service animal notes and quiet-room needs when guests provided them, and confirm the venue can actually provide those spaces.


## Capacity and contingency

For export dietary and access summary, write a short contingency: if the primary laptop fails, which backup device opens the project; if the printer fails, which file is already on a USB stick; if the venue network fails, which steps still work offline. Contingencies written after the failure are just stories. Contingencies written before the event are operations.

Assign names, not roles only—roles change when people call in sick. List those people by name in the notes file that sits beside the export dietary and access summary export.
