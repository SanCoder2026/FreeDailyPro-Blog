## Worked example

Closing-night raffle: guest list names, extra tickets for VIP entries, winners+backups recorded, certificates for top three, tote-bag merch order sized from attendance.

## Steps

1. Open the tool; try a sample then replace names.
2. Load names from guest list or paste one per line.
3. Decide whether repeats count once; set extra tickets if needed.
4. Draw winners and backups together; download the draw record.
5. Publish winners only after the record is saved.
6. Plan merchandise quantities from attendance, not hope.
7. Make certificates for prize tiers that need paper.
8. Print labels for merch or prize packs.
9. Save the project with the draw file for audits.
10. Do not re-draw casually after results were announced.

## Common mistakes

- Re-drawing after public announcement.
- No backup winners when a person is absent.
- Merch ordered after the draw without sizes.
- Losing the draw record.
- Mixing staff entries without a clear rule.

## Backup winners

Draw backups at the same time. If winner three is absent, backup one steps up without a suspicious second random event.

## Audit file

Keep the download record with timestamp and entry list. Finance and sponsors may ask how the draw worked.

## Extra tickets

If VIPs get three chances, encode Ana x3 rather than pasting the name three times by hand error-prone.

## Certificate tone

Match certificate language to the prize. A $10 gift card does not need a formal seal; a scholarship prize does.

## Merch cut-off

Order merch from a frozen headcount date. Late RSVPs get a rain-check policy you state in writing.

## Production log

Write one line of settings and export date next to the final file for the run prize draw and event merch job so a reprint does not start from zero.

## Eligibility rules on the screen

State staff eligibility, age limits, and one-entry rules before names go in. Changing rules after the draw looks unfair even when it is not.

## Certificate print stock

Use heavier paper for certificates you expect people to keep. Thin flyer stock feels accidental for top prizes.

## Public announcement script

Read winners from the saved draw record, not from memory. If a winner is absent, move to the backup listed on the same record without a new random event in front of the audience.

For merch pickup, print labels with size and name when personalization exists. Unlabeled boxes become a long line of unhappy people after the keynote.

## Archive and naming for run prize draw and event merch

Store final exports under a folder named with the event or project code and the ISO date. Inside, keep `exports/`, `project/`, and `notes.txt`. In notes.txt for run prize draw and event merch, record approver name, device used on the day, and version label. That beats a desktop full of final2 copies.


## Extra field practice

Publish eligibility rules on the same screen guests see when they enter. Staff ineligible? Say so. Photograph the draw record screen as a backup to the download. For certificates, use the event’s legal entity name and date; informal nicknames on certificates look unprofessional in HR files later.


## Capacity and contingency

For run prize draw and event merch, write a short contingency: if the primary laptop fails, which backup device opens the project; if the printer fails, which file is already on a USB stick; if the venue network fails, which steps still work offline. Contingencies written after the failure are just stories. Contingencies written before the event are operations.

Assign names, not roles only—roles change when people call in sick. List those people by name in the notes file that sits beside the run prize draw and event merch export.
