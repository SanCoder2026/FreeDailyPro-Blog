## Lessons while fresh

Capture what to repeat and what to change within 48 hours. Specific beats vague (“move registration doors” beats “improve flow”).

## Finance honesty

If foreign-currency rows were excluded, say how many. Leadership hates silent gaps.

## Thank-you section

Name partners who saved the day. Relationships are part of the report’s job.

## Programme truth

If a session failed, say so kindly. Future agendas improve only when failure is written down.

## Debrief agenda

Use the lessons list as the only debrief agenda so the meeting does not wander into war stories without decisions.

## Production log

For the write event closure report pdf workflow, write one line of settings and export date beside the final download so a reprint does not rely on memory.

## Photo appendix optional

If you attach photos, pick five that teach something (queue length, signage miss, stage sightline). Dozens of party photos dilute the report.

## Owner per lesson

Every lesson gets an owner and a target month. Lessons without owners are decorations.

## Decision log

Convert each lesson into a decision: keep, change, or drop. Attach owners and months. A closure report that only narrates the weekend will be skimmed once and forgotten.

Include a short vendor keep/drop table so procurement does not re-hire a problem vendor next year by accident.

## Extra field practice

Invite finance and programme leads to add two bullets each before you finalize lessons. Single-author closure reports miss whole failure modes. Put attendance methodology in a footnote so nobody re-litigates whether no-shows counted. Ship the PDF within five business days while contractors still answer email about what went wrong.


## Capacity and contingency

For write event closure report pdf, write a short contingency: if the primary laptop fails, which backup device opens the project; if the printer fails, which file is already on a USB stick; if the venue network fails, which steps still work offline. Contingencies written after the failure are just stories. Contingencies written before the event are operations.
