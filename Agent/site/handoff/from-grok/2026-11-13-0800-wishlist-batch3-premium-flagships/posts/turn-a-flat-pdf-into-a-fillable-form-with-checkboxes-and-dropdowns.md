## Real fields, not drawn fake boxes

Live product facts:

- Fields are standard PDF form fields. The result can be filled in Acrobat Reader, many browser viewers, phones, or [Fillable Forms](https://www.freedailypro.com/tool/fillable-forms) on FreeDailyPro.
- Open an existing PDF (pages kept) or start blank.
- Name each field clearly—the name is what appears in exported field data. Names must be unique, except radios that share a name as one group.
- A **signature area** is a drawn “Sign here” box so the signer knows where to sign; place the actual signature with [Sign PDF](https://www.freedailypro.com/tool/sign-pdf) (the tool can hand off).
- Does **not** auto-detect fields from a scan; placement is manual. Not cryptographic digital signatures or password protection.
- PDF is opened and changed in the browser and erased when you close the tab.

Related: fill an already-fielded form in [Fillable Forms](https://www.freedailypro.com/tool/fillable-forms); flatten when you need a non-editable snapshot with [Flatten PDF](https://www.freedailypro.com/tool/flatten-pdf) if available on your workflow.

## Naming fields so exports make sense

Keisha bans spaces in field names (`full_name` not `Full Name`). Dropdown values match the property codes finance already uses. Radio groups for “yes/no pets” share one name so only one choice sticks.

She keeps a one-row spreadsheet of field names next to the form version number. When a developer later pulls field data, the names still match last year’s export.

## Common mistakes

- Drawing lines that only look like fields but are not form fields.
- Duplicate field names on unrelated inputs.
- Expecting OCR to invent fields from a photo of a paper form.
- Sending the form without a test fill.
- Using PDF Editor text boxes instead of real fields when applicants must type answers.
- Making checkboxes smaller than a finger can tap on a phone.

## Intake rollout Keisha uses

Week 1: convert the application only. Week 2: add the move-in checklist as a second form. She never combines both into one 20-page monster until staff ask for it. Each form version ships with a short staff note: “type on screen, do not print unless the applicant has no device.”

## Accessibility habit

She makes text fields slightly taller than the printed line and tests on a phone PDF viewer once. Tiny fields fail on mobile and create support tickets. Dropdown lists stay short—under a dozen building codes—so phones do not scroll forever.

## FAQ

**Are the fields real AcroForm-style fields?**
Yes. They are standard fillable PDF form fields for common readers and Fillable Forms.

**Can I add fields to a PDF that already has some?**
Yes. New fields are added alongside; watch for name clashes.

**Is the PDF uploaded?**
No. It is changed in the browser and cleared when the tab closes.

**Does the tool detect fields from a scan automatically?**
No. You place each field. Plan ten quiet minutes for a one-page form.

**How do applicants sign?**
Use the signature area as a visual guide, then Sign PDF (or the handoff the tool offers) for the actual signature graphic.

**What if staff still print everything?**
Ship the fillable file and a one-page “type here” screenshot. Culture change takes longer than field placement.
