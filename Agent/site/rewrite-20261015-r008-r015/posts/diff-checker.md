## Step-by-step workflow

1. Copy the previous version of the text.
2. Copy the proposed version.
3. Open [Diff Checker](https://www.freedailypro.com/tool/diff-checker) and paste both sides.
4. Walk every highlighted change — not only the first screen.
5. For broader overlap questions, use [Text Similarity Checker](https://www.freedailypro.com/tool/text-similarity-checker).
6. For structured config JSON, format first with [JSON Formatter](https://www.freedailypro.com/tool/json-formatter) so diffs are readable.
7. Record who approved material changes.
8. Publish only after review notes are done.

## Common mistakes

- Skimming only the first diff hunk
- Comparing minified JSON without formatting
- Trusting email “final” in the subject line without a diff
- Mixing Windows and Unix line endings that create noisy false changes
- Editing the live production copy while reviewing another buffer

## Honest limits

Diff tools show text changes; they do not prove legal compliance or semantic sameness. Binary files need other workflows. Human judgment still owns approval.


## Policy and terms updates

Highlight fee changes, date changes, and liability clauses. Require a second reader on those hunks.

## Code and config

Format JSON first. Diff strings carefully when secrets might appear — do not paste production secrets into unnecessary places.

## Marketing copy freezes
